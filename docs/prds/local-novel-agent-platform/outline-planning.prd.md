# 大纲规划、时间线与伏笔 PRD

## 1. 背景

中文长篇网文的大纲不是一份静态文本，而是一套持续服务章节生产的结构资产。它需要同时管理总纲、分卷、章纲、时间线、伏笔、角色变化和阶段爽点，并在章节生成、评审和记忆更新中被反复读取。

大纲页应该是“故事结构驾驶舱”，而不是一个单一长文本编辑器。

## 2. 目标

1. 支持作者查看和维护总纲、卷纲、章纲、时间线与伏笔账本。
2. 帮助作者判断故事主线、章节目标、角色变化和伏笔回收是否连续。
3. 为章节生产工作流提供结构化输入。
4. 提供内置 Agent 任务入口，辅助生成、检查和修复大纲资产，但不暴露 Agent 配置。

## 3. 非目标

1. 不做可视化 Agent 编排器。
2. 不做 Prompt、Skill 或工作流节点配置 UI。
3. MVP 不做复杂图谱编辑器、自由拖拽关系图或多人协作批注。
4. MVP 不承诺一键生成完整长篇全书大纲。

## 4. 核心判断

### 4.1 简介是否放在大纲页

简介不应主要放在大纲页。

归属规则：

- 小说概览页负责维护简介体系，包括一句话 hook、创作简介和对外简介。
- 大纲页只展示故事基准摘要，包括 hook、核心卖点、主冲突、当前卷目标和创作简介节选。
- 大纲页可以提供轻量编辑或跳转入口，但不把对外简介作为核心编辑对象。

原因：

1. 简介解决“这本书卖什么”，大纲解决“故事如何推进”。
2. 章节生产需要读取简介，但简介不是大纲结构本身。
3. 分离后可以避免大纲页承担过多项目管理职责。

### 4.2 是否需要时间线

需要，但分阶段实现。

MVP 做“故事事件时间线”，重点解决逻辑一致性，不追求复杂视觉效果。

后续再扩展：

- 可视化时间轴
- 角色个人线
- 势力线
- 因果图
- 倒叙、插叙、回忆段标记

## 5. 功能范围

### 5.1 故事基准区

展示当前大纲规划的上游约束。

字段建议：

- 一句话 hook
- 核心卖点
- 主冲突
- 故事引擎
- 当前卷目标
- 结局方向
- 创作简介节选

用途：

1. 让作者进入大纲页时先确认方向。
2. 让 Agent 大纲任务拥有稳定上游输入。
3. 防止章纲规划偏离立项定位。

### 5.2 总纲

总纲描述整本书的主线推进。

字段建议：

- 故事起点
- 主线目标
- 阶段推进
- 核心反转
- 高潮设计
- 结局方向
- 主角成长线
- 主要矛盾升级路径

状态建议：

- 草稿
- 待确认
- 已确认
- 需修订

### 5.3 分卷规划

分卷规划负责把总纲拆成阶段目标。

字段建议：

- 卷序号
- 卷标题
- 卷目标
- 卷核心冲突
- 主要爽点
- 角色变化
- 关键事件
- 预计章节范围
- 当前状态

交互要求：

1. 大纲页应允许用户新增卷，新增结果默认进入草案状态。
2. 大纲页应允许用户删除未锁定或未确认的卷。
3. 删除卷前必须提示影响范围，包括章纲、时间线、伏笔和已确认 canon。
4. 已产生正式章节或 canon 事实的卷，后续实现应禁止直接删除，只允许归档、拆分或迁移。
5. 除故事基准、总纲和全书时间线总览外，章纲、伏笔、结构检查和 Agent 修改任务应优先围绕当前卷展开。

### 5.4 章纲列表

章纲是章节生产的直接输入。

字段建议：

- 章节序号
- 章节标题
- 所属卷
- 章节目标
- 剧情摘要
- 出场角色
- 关键冲突
- 章末钩子
- 关联伏笔
- 关联时间线事件
- 状态：待生成、草稿、评审中、待确认、已确认

### 5.5 时间线

MVP 时间线以事件列表形式实现。

字段建议：

- `eventId`
- `novelId`
- 事件名称
- 事件摘要
- 故事内时间
- 叙事位置：关联卷、章节
- 涉及角色
- 因果关系
- 是否 canon
- 风险备注

时间线需要支持两种排序：

1. 故事内时间顺序。
2. 叙事章节顺序。

MVP 页面可以先展示故事内时间顺序，并标明关联章节。

### 5.6 伏笔账本

伏笔账本负责记录埋设、推进和回收。

字段建议：

- `foreshadowingId`
- `novelId`
- 伏笔名称
- 内容摘要
- 埋设章节
- 计划回收章节
- 当前状态：已埋设、推进中、待回收、已回收、风险
- 关联角色
- 关联设定
- 风险备注

### 5.7 结构检查

大纲页需要展示结构风险。

检查项包括：

- 主线断裂
- 角色动机不足
- 时间顺序冲突
- 伏笔未回收
- 章节目标重复
- 爽点密度不足
- 卷目标与章纲不一致

### 5.8 Agent 操作入口

允许展示以下任务入口：

- 生成总纲
- 扩展卷纲
- 生成前 10 到 20 章章纲
- 检查大纲问题
- 修复时间线冲突
- 补充伏笔回收方案
- 根据当前章纲生成下一章生产任务

限制：

1. 只展示任务名称、输入摘要、输出结果和状态。
2. 不展示 Agent 角色配置、Prompt 内容、Skill 权限或 LangGraph 节点图。
3. 每个任务必须携带 `novelId`。

## 6. 长篇规模化处理策略

长篇网文通常会达到数百章甚至上千章，大纲、时间线、伏笔和角色状态都不能按“全量铺开”的方式展示或读取。系统必须把这些资产设计成分层、分卷、可检索、可过滤、可摘要的结构。

### 6.1 分层结构

大纲资产至少分为五层：

1. 全书总纲：只描述全书级主线、结局方向、主角成长和核心矛盾。
2. 卷纲：描述单卷目标、卷核心冲突、主要爽点和阶段反转。
3. 阶段纲：建议每 20 到 50 章形成一个阶段，用于承接卷目标与章纲。
4. 章纲：服务具体章节生产，不应在默认视图一次性展示全量。
5. 当前章节上下文：生产或修订单章时实际读取的最小必要上下文。

### 6.2 默认工作窗口

大纲页默认不展示全量资产，而是展示“当前工作窗口”。

默认工作窗口包括：

- 当前卷。
- 当前阶段。
- 当前章前后 10 到 20 章章纲。
- 当前卷核心时间线事件。
- 当前章相关角色状态。
- 当前章相关伏笔。
- 全书级核心 canon。
- 当前风险项。

用户需要查看历史或远期内容时，通过筛选、搜索或跳转进入。

### 6.3 章纲分页与筛选

章纲视图必须支持：

- 按卷筛选。
- 按阶段筛选。
- 按章节范围筛选。
- 按状态筛选：待生成、草稿、评审中、待确认、已确认。
- 按关键词搜索：标题、目标、钩子、角色名、伏笔名。
- 分页或虚拟滚动。

MVP 可以先用分页与筛选 mock 表达，真实数据接入时再实现后端分页。

### 6.4 时间线分层

时间线不能只有一条无限长列表。至少需要支持以下视图：

- 主线时间线。
- 当前卷时间线。
- 角色个人时间线。
- 势力或组织时间线。
- 伏笔时间线。
- 设定变更时间线。

时间线事件必须支持过滤：

- 所属卷。
- 所属阶段。
- 关联章节。
- 关联角色。
- 事件类型。
- 重要级别：核心、重要、普通。
- canon 状态。
- 风险状态。

MVP 默认展示当前卷核心事件，并允许切换到角色、伏笔和 canon 过滤。

### 6.5 伏笔账本规模化

伏笔账本必须支持按状态和范围管理。

过滤条件包括：

- 已埋设。
- 推进中。
- 待回收。
- 已回收。
- 风险。
- 当前卷。
- 当前阶段。
- 关联角色。
- 关联设定。

默认优先展示待回收、风险和当前工作窗口相关伏笔。

### 6.6 摘要层级

为避免 Agent 每次读取过量上下文，系统必须维护摘要层级。

摘要类型包括：

- 全书摘要。
- 卷摘要。
- 阶段摘要。
- 章节摘要。
- 角色阶段状态摘要。
- 伏笔状态摘要。
- 时间线窗口摘要。

章节通过用户确认后，记忆更新工作流应同步更新相关摘要。

### 6.7 Agent 上下文包

Agent 不应默认读取全量大纲、全量时间线或全量伏笔账本。章节生产、评审和修订应读取由系统组装的上下文包。

上下文包建议包含：

- 小说基础定位。
- 当前卷目标。
- 当前阶段目标。
- 当前章纲。
- 前 3 到 5 章摘要。
- 相关角色状态。
- 相关设定。
- 相关伏笔。
- 相关时间线事件。
- 必须遵守的 canon。
- 当前风格约束。

上下文包必须绑定 `novelId`，并记录生成时使用的资产版本或时间戳，便于后续追踪。

### 6.8 页面性能要求

长篇资产页面需要避免一次性渲染大量行。

后续真实实现时应优先考虑：

- 后端分页。
- 前端虚拟列表。
- 搜索防抖。
- 按需加载详情。
- 折叠长文本。
- 默认只请求当前工作窗口。

## 7. 页面设计要求

### 6.1 大纲页信息架构

建议采用分区式工作台：

1. 顶部故事基准区。
2. 左侧或上方结构概览：总纲、当前卷、风险数量。
3. 主要区域：总纲、分卷规划、章纲列表。
4. 辅助区域：时间线、伏笔账本、结构检查、Agent 任务入口。

### 6.2 MVP 交互

MVP mock 页面需要支持：

- 查看故事基准。
- 查看总纲摘要。
- 查看分卷规划。
- 查看章纲列表。
- 查看时间线事件。
- 查看伏笔账本。
- 查看结构检查结果。
- 展示大纲相关 Agent 任务入口按钮。

第一版可以是静态 mock，不要求持久化编辑。

## 8. 数据要求

所有大纲相关实体必须绑定 `novelId`。

建议后续领域模型：

- `StoryBaseline`
- `MasterOutline`
- `VolumePlan`
- `ChapterPlan`
- `TimelineEvent`
- `ForeshadowingItem`
- `OutlineIssue`
- `OutlineStage`
- `ContextBundle`

## 9. 工作流关系

大纲规划能力应连接以下工作流：

- `outline-planning-graph`
- `chapter-production-graph`
- `chapter-review-graph`
- `memory-update-graph`

关键约束：

1. 章节生产必须读取当前章纲和小说记忆。
2. 章节确认后，记忆更新工作流应同步更新时间线、伏笔状态和 canon。
3. 大纲修订不得自动覆盖已确认章节事实，必须进入待确认状态。

## 10. MVP 验收标准

1. 大纲页能同时展示总纲、卷纲、章纲、时间线、伏笔和结构风险。
2. 简介只作为故事基准摘要出现在大纲页，主要维护位置仍在小说概览页。
3. 时间线以事件列表方式呈现，并明确关联章节和 canon 状态。
4. 页面提供大纲相关 Agent 任务入口，但不出现配置 UI。
5. 所有 mock 数据都按 `novelId` 隔离。
