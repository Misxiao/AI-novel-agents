# 小说基础信息与立项资产 PRD

## 1. 背景

小说基础信息不是单纯的项目元数据，而是后续大纲、章节生产、评审和记忆更新的创作基准。平台需要让每本小说拥有清晰、可追踪、可被 Agent 读取的立项资产，同时避免把 Agent、Prompt、Skill 配置暴露给用户。

该能力服务于“创建一本小说后，作者和系统都知道这本书要写什么、卖给谁、靠什么持续推进”。

## 2. 目标

1. 支持用户维护每本小说的基础信息、创作定位、简介体系和风格方向。
2. 为大纲规划、章节生成、评审和记忆更新提供稳定的上游输入。
3. 在小说概览页集中展示当前创作状态、关键资产完整度和下一步行动。
4. 保证所有基础资产都绑定 `novelId`，不与其他小说混用。

## 3. 非目标

1. 不提供 Agent 配置、Prompt 管理或 Skill 管理入口。
2. 不把平台对外发布、真实账号登录、自动发文作为本阶段能力。
3. 不把外部参考语料直接并入小说资产，除非用户确认授权。
4. 不做多人协作、权限管理和云端同步。

## 4. 用户场景

### 4.1 新建小说后补全立项

用户创建小说后，系统引导用户补全书名、题材、目标读者、核心卖点、一句话 hook、创作简介、目标体量和风格方向。

### 4.2 进入创作中心时快速判断状态

用户打开某本小说时，优先看到当前阶段、章节进度、最近任务、资产缺口、待确认事项和下一步建议。

### 4.3 章节生成前校准故事基准

用户准备生成章节前，可以确认当前小说的 hook、主冲突、当前卷目标、风格约束和禁用表达是否仍然有效。

### 4.4 对外简介与内部创作简介分离

作者需要给读者看的简介，也需要给自己和 Agent 看的创作说明。两类文本目的不同，不能混为一个字段。

## 5. 功能范围

### 5.0 新建小说流程

新建小说不应只是创建一条空记录，而应完成从基础灵感到立项基准、再到大纲草案的最短闭环。

推荐流程：

1. 基础灵感：用户输入书名、题材、一句话灵感、目标读者、预期体量和风格倾向。
2. 立项基准：系统基于基础灵感生成 hook、核心卖点、主冲突、故事引擎和风险提示草案。
3. 用户确认立项基准：确认后才能进入大纲草案生成。
4. 大纲草案：系统生成总纲占位、初始分卷规划和当前卷工作窗口。
5. 创建小说：写入小说基础信息、立项资产和初始大纲草案，进入该小说的大纲页。

约束：

1. 新建流程生成的是草案，不直接进入章节正文生成。
2. 大纲草案必须由用户确认或继续细化后，才能作为章节生产输入。
3. 新建流程不得暴露 Agent、Prompt、Skill 或工作流节点配置。
4. 新建结果必须绑定新的 `novelId`，并进入独立命名空间。

### 5.1 基础信息

每本小说必须包含：

- `novelId`
- 书名
- 题材与子题材
- 当前阶段：立项、大纲、连载、修订、归档
- 目标章节数或目标字数
- 当前卷
- 已完成章节数
- 最近更新时间
- 质量状态：健康、关注、风险

### 5.2 立项定位

立项定位用于回答“这本书为什么值得追”。

字段建议：

- 一句话 hook
- 核心卖点
- 目标读者
- 情绪承诺
- 主冲突
- 故事引擎
- 主角成长方向
- 预期体量
- 风险提示

### 5.3 简介体系

简介需要拆成三类：

| 类型 | 用途 | 主要展示位置 | 是否给 Agent 使用 |
| --- | --- | --- | --- |
| 一句话 hook | 快速识别卖点和主冲突 | 小说列表、概览页、大纲页摘要区 | 是 |
| 创作简介 | 给作者和 Agent 使用的内部说明 | 小说概览页 | 是 |
| 对外简介 | 未来面向读者的平台文案 | 小说概览页 | 默认否，可作为后续发布资产 |

规则：

1. 小说概览页是简介的主要维护位置。
2. 大纲页只显示必要的故事基准摘要，可提供轻量编辑入口，但不作为简介主编辑页。
3. 章节生成默认读取一句话 hook 和创作简介，不默认读取对外简介。

### 5.4 风格方向

风格方向属于小说资产，不属于 Prompt 配置。

字段建议：

- 文风关键词
- 节奏倾向
- 对白密度
- 叙述视角
- 禁用表达
- 角色口吻约束摘要
- 参考风格说明

### 5.5 资产完整度

概览页需要展示基础创作资产的完整度，用于判断是否可以进入章节生产。

资产项包括：

- 基础信息
- 立项定位
- 简介体系
- 世界观
- 角色库
- 总纲
- 卷纲
- 章纲
- 伏笔账本
- 风格档案

每项状态建议：

- `missing`：缺失
- `draft`：草稿
- `ready`：可用
- `needs_review`：需要复核

### 5.6 下一步行动

概览页应该展示基于当前状态的行动入口。

MVP 操作包括：

- 完善立项信息
- 生成或更新总纲
- 补齐角色动机
- 检查资产缺口
- 进入大纲页
- 进入章节生产
- 查看最近任务

这些入口触发的是内置工作流任务，不暴露底层 Agent 配置。

## 6. 页面设计要求

### 6.1 小说概览页

概览页需要成为一本小说的“状态仪表盘”。

主要区域：

1. 故事基准：书名、题材、hook、创作简介、当前卷目标。
2. 进度状态：章节进度、记忆健康度、质量状态、最近任务。
3. 立项定位：核心卖点、目标读者、情绪承诺、主冲突、故事引擎。
4. 简介体系：创作简介、对外简介、一句话 hook。
5. 资产完整度：基础资产状态和风险。
6. 待处理事项：按优先级展示作者确认、设定缺口、修订任务。

### 6.2 小说列表页

小说列表只展示高信号摘要：

- 书名
- 题材
- hook
- 当前阶段
- 章节进度
- 当前卷
- 最近任务
- 质量分

## 7. 数据要求

所有实体必须绑定 `novelId`。

建议后续领域模型：

- `Novel`
- `NovelFoundation`
- `NovelPitch`
- `NovelSynopsis`
- `StyleProfile`
- `AssetReadiness`

## 8. Agent 与工作流要求

允许出现以下任务入口：

- 立项诊断
- 卖点强化
- 简介改写
- 风格约束提炼
- 资产完整度检查

约束：

1. 前端只展示任务入口和结果，不展示 Prompt、Skill 或工作流节点配置。
2. 任务输入必须携带 `novelId`。
3. 任务输出必须以小说资产形式写入当前小说命名空间。

## 9. MVP 验收标准

1. 用户可以在概览页看到一本小说的创作定位、简介体系和当前进度。
2. 用户可以明确区分创作简介与对外简介。
3. 大纲页能够读取 hook 和创作简介摘要，但简介主要维护位置仍在概览页。
4. 页面上所有 mock 数据都体现 `novelId` 隔离。
5. 不出现 Agent 配置、Prompt 管理或 Skill 管理 UI。
