# CLI Help 友好描述设计

## 背景

当前 CLI 顶层 `help` 按首级命令统计数量，展示为“novel 5 个命令”等内部盘点信息。用户无法直接判断每个入口能完成什么任务，并且 `help`、`context`、`exit`、`quit` 也被混在业务命令分组中。

## 目标

顶层 `help` 应优先说明用户可以完成的工作，而不是展示命令数量。分组帮助也应先解释该分组的用途，再列出可用子命令。单命令帮助保持现有行为。

## 展示结构

顶层帮助分为三部分：

1. `创作命令`：`novel`、`preflight`、`outline`、`chapter`。
2. `查询命令`：`asset`、`task`。
3. `工作台命令`：`context`、`help`、`exit`。

每个入口右侧展示稳定、面向用户的用途说明：

```text
AI 小说创作工作台

创作命令:
  novel       创建、查看和管理小说项目
  preflight   从创作想法生成基础盘、设定和初始大纲
  outline     查看、修改和确认小说大纲
  chapter     生成、评审并修订章节草稿

查询命令:
  asset       查看小说基础盘、设定和大纲草案
  task        查看工作流任务及运行结果

工作台命令:
  context     查看当前小说和数据库位置
  help        查看命令说明
  exit        退出工作台

输入 help <分组或命令> 查看详细说明。
```

`quit` 是 `exit` 的别名，不在顶层帮助中重复展示。命令仍可正常执行，也可通过 `help quit` 查看说明。

## 实现方式

在 `CommandRegistry` 的帮助生成逻辑中维护有序的展示分区和用途文案。仅展示当前注册表中实际存在的入口，避免测试注册表或后续裁剪命令时出现无效帮助项。

查询分组帮助时，复用同一份用途文案，输出分组用途和子命令列表。例如：

```text
novel - 创建、查看和管理小说项目

可用子命令:
  novel create                 创建空小说
  novel list                   查看小说列表
  novel show                   查看小说详情
  novel update                 修改小说基础信息
  novel use                    切换当前小说

输入 help novel <子命令> 查看详细说明。
```

未配置专门用途文案的分组仍使用通用标题并列出匹配命令，保证 `CommandRegistry` 可用于测试或扩展命令。顶层单命令（如 `help context`）继续展示完整用法和示例。

不修改命令解析和命令执行。

## 测试

在 CLI 核心测试中验证：

- 顶层帮助包含三个展示分区。
- 顶层帮助包含面向用户的用途说明。
- 顶层帮助不再包含“个命令”。
- `quit` 不在顶层工作台命令列表中重复展示。
- 分组帮助包含分组用途、可用子命令和进一步查询提示。
- 未配置专门用途文案的分组仍可正常生成帮助。
- 单命令帮助继续展示已有命令摘要、用法和示例。
