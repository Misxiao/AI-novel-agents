# Agent 与 CLI 开发路线图

## 1. 文档目的

本文档记录当前项目在不依赖 `apps/web` 和 `apps/api` 的情况下，已经具备的 Agent、Workflow、CLI 和本地资产能力，并从重度使用 CLI 进行长篇小说创作的角度，明确后续开发顺序和阶段验收标准。

本文档是后续 Agent 底层开发的执行依据。功能状态发生变化时，应同步更新本文档，避免项目文档、实际代码和开发优先级长期不一致。

本文档不替代 PRD、技术设计或开发手册：

- PRD 说明产品目标和用户需求。
- 技术设计说明系统边界和实现原则。
- 开发手册说明日常工程约定。
- 本文档说明当前完成度、真实使用缺口和下一步开发顺序。

## 2. 当前总体判断

当前项目已经跑通以下基础链路：

```txt
创建小说
-> 生成小说基础盘、设定和初始大纲
-> 评审前置资产
-> 修改并确认大纲
-> 装配章节上下文
-> 生成或读取章纲
-> 生成章节执行计划和正文
-> 评审正文
-> 必要时自动修订
-> 保存章节草稿和任务记录
```

这意味着项目已经具备一条可通过 CLI 验证的单章生产链，但还没有形成可以稳定支撑数十万字连载的完整闭环。

当前最重要的缺口不是继续增加生成能力，而是：

1. 章节草稿缺少正式确认和版本治理。
2. 已确认章节尚不能形成结构化小说记忆。
3. 下一章生产尚未完整继承上一章确认后的状态变化。
4. 评审、修订、AgentRun 和质量门禁尚未作为独立资产完整持久化。
5. 长篇创作需要的角色、时间线、伏笔、canon 和作者决策还缺少独立查询与维护入口。

## 3. 已实现能力

### 3.1 Agent 基础运行层

当前已经实现统一的 `ChatModel`、Agent runtime、capability 输入输出和 AgentRun 元数据。

已实现的 Agent 包括：

| Agent | 已实现能力 | 当前状态 |
| --- | --- | --- |
| `inspiration` | 根据初步想法生成小说基础盘草案 | 可用 |
| `setting` | 生成世界观、人物种子、关系种子和风格约束草案 | 可用 |
| `outline` | 生成初始大纲、修改总纲、修改指定卷纲 | 可用 |
| `plan` | 生成单章章纲、生成章节写作执行计划 | 可用 |
| `chapter` | 生成章节、修订章节、重写场景、扩写、压缩、风格处理 | 可用 |
| `review` | 评审基础盘、设定、大纲、大纲修改候选和章节正文 | 可用 |
| `memory` | 上下文检索、canon 提取和记忆更新 | 未实现 |
| `analytics` | 阅读数据分析和调整建议 | 未实现 |
| `director` | 流程选择和跨 Workflow 调度 | 未实现 |

所有现有 Agent 输出均以草案、候选或报告为主，不应直接写入正式 canon。

### 3.2 中文网文专项能力

当前已经内置章节正文生产需要的专项模块链：

```txt
plot_logic
-> character_consistency
-> transition
-> dialogue
-> chapter_ending
-> anti_ai_voice
-> consistency_review
```

已经落地的内容包括：

- 中文网文专项模块类型。
- 章节生产模块顺序。
- 章节完稿一致性审查要求。
- 章节写作技法资源。
- 模块索引、素材包和外部来源登记。
- 剧情逻辑、人物一致性、转场、对白、章末和去 AI 味等结构化评审维度。

当前专项能力主要服务章节生产。完整的任务路由器、规划阶段模块和可扩展素材检索仍需继续完善。

### 3.3 Workflow 能力

当前已经实现以下项目自有 Workflow：

| Workflow | 当前能力 | 输出状态 |
| --- | --- | --- |
| `novel-preflight` | 依次生成并评审基础盘、设定和初始大纲 | 等待用户确认或失败 |
| `revise-master-outline` | 根据自然语言生成总纲修改候选、执行策略校验和评审 | 等待用户确认或需修订 |
| `revise-volume-outline` | 修改指定卷并阻止跨卷越权修改 | 等待用户确认或需修订 |
| `confirm-outline` | 确认前置资产和大纲，生成正式章纲资产 | 成功 |
| `write-next-chapter` | 装配上下文、生成章纲或读取章纲、规划正文、生成、评审和自动修订 | 成功并保存草稿 |

`write-next-chapter` 已经支持：

- 使用已有章纲或自动生成章纲。
- 生成章节写作执行计划。
- 输出初稿。
- 结构化章节评审。
- 按质量门禁自动修订。
- 在分数下降或达到门禁后停止修订。
- 返回初稿、最终候选稿、评审报告、修订历史和质量门禁结果。
- 保存章节草稿和 WorkflowTask。

当前章节 Workflow 的“成功”表示生成流程执行完成，不表示章节已经得到作者确认或进入正式 canon。

### 3.4 SQLite 与 Repository

当前已经实现本地 SQLite 持久化和 repository 边界，支持：

- 创建、查询和更新小说项目。
- 按 `novelId` 隔离小说数据。
- 保存和查询 WorkflowTask。
- 保存基础盘、设定和大纲前置草案。
- 保存和查询大纲修改版本。
- 确认前置资产与正式大纲。
- 保存和查询章纲。
- 保存章节草稿上下文。
- 查询已确认章节上下文。
- 为章节生产装配近邻章节和章纲窗口。

章节上下文窗口已经可以区分：

- 最近章节全文。
- 较远章节摘要。
- 上一章结尾。
- 后续章节目标。
- 前后章纲窗口。
- 世界规则、风格约束和禁用表达。

尚未独立持久化的内容包括：

- 章节正式版本链。
- 章节评审报告。
- 自动修订历史。
- 质量门禁结果。
- AgentRun 明细。
- 角色状态。
- canon 事实。
- 时间线和伏笔状态变化。
- 作者决策与评审豁免。

### 3.5 CLI 工作台

当前 CLI 已支持交互模式和单次命令模式，并具备：

- 小说创建、列表、查看、切换和基础信息修改。
- 查看前置资产。
- 查看当前大纲和大纲版本历史。
- 查看任务列表和任务详情。
- 运行前置资产 Workflow。
- 修改总纲和卷纲。
- 确认大纲。
- 运行章节生产 Workflow。
- 使用真实模型或离线 mock 模型。
- 使用 SQLite 小说项目或临时 mock 上下文。
- 通过 `--json` 输出完整结构化结果。

CLI 当前已经适合开发验证和短流程试写，但还缺少职业作者长期使用需要的章节、记忆、角色、伏笔、版本和恢复命令。

### 3.6 LLM 接入

当前已经实现：

- 统一 `ChatModel` 接口。
- OpenAI-compatible 请求实现。
- DeepSeek 环境变量配置和默认模型创建。
- provider 错误和配置错误分类。
- token usage 记录。
- Agent 注入 fake model 和 mock model 的能力。

当前默认供应商只有 DeepSeek。多供应商路由、本地模型、重试和调用成本统计尚未实现。

### 3.7 尚为空壳的包

以下包目前尚未形成可用能力：

- `packages/domain`
- `packages/memory`
- `packages/shared`

后续不应为了填充目录而提前建立宽泛抽象。应由章节确认与记忆闭环的真实需求推动这些包逐步落地。

## 4. CLI 作者视角的核心缺口

### 4.1 章节没有完成正式确认

目前章节 Workflow 结束后只得到草稿。作者缺少查看、比较、接受和拒绝候选稿的正式操作。

目标命令形态：

```txt
chapter list
chapter show <chapterNo>
chapter diff <chapterNo>
chapter confirm <chapterNo>
chapter reject <chapterNo>
```

章节确认后必须：

- 创建不可变的正式章节版本。
- 推进小说的已完成章节数。
- 更新章纲状态。
- 保留原始草稿、最终候选稿和确认版本之间的关系。
- 触发章节记忆提取。
- 允许下一章读取该章节的正式摘要和状态变化。

### 4.2 缺少小说记忆系统

当前 `packages/memory` 尚为空。长篇写作不能长期依赖全量正文、大纲和临时 Prompt。

最小记忆范围包括：

- Canon Memory：已经确认的事实。
- Working Memory：当前卷、近期章节摘要和当前局面。
- Character State：角色目标、情绪、关系、身体和能力状态。
- Planning Memory：总纲、卷纲、章纲、时间线和伏笔。
- Style Memory：风格要求、角色口吻、禁用表达和作者偏好。
- Run Memory：任务、评审、修订和模型调用记录。

所有小说私有记忆必须绑定 `novelId`。未确认章节不得写入正式 canon。

### 4.3 缺少章节版本管理

职业创作中的修改不能直接覆盖正式稿。系统需要保留：

- 草稿版本。
- 自动修订版本。
- 作者确认版本。
- 确认后的人工修改版本。
- 版本来源、修改指令和差异摘要。

目标命令形态：

```txt
chapter history <chapterNo>
chapter diff <chapterNo> --from <version> --to <version>
chapter revise <chapterNo> --instruction <内容>
chapter checkout <chapterNo> --version <version>
```

### 4.4 缺少可解释的上下文装配

作者需要知道一次章节生成实际读取了哪些资产、忽略了哪些内容，以及缺失资产是否影响可靠性。

目标命令形态：

```txt
context inspect --chapter-no <chapterNo>
context explain --chapter-no <chapterNo>
chapter readiness --chapter-no <chapterNo>
chapter write --chapter-no <chapterNo> --dry-run
```

检查结果至少包含：

- 当前章纲和卷目标。
- 近邻章节窗口。
- 角色状态。
- 世界规则。
- canon 事实。
- 待推进和待回收伏笔。
- 风格约束。
- 缺失资产。
- 来源引用。
- 上下文预算与省略说明。

### 4.5 结构化资产缺少独立维护入口

角色、设定、时间线和伏笔不应长期只存在于大纲 JSON 或 Prompt 中。

后续需要独立查询和维护：

```txt
character list
character show <角色>
character history <角色>
world-rule list
timeline list
foreshadow list
foreshadow show <id>
canon list
canon conflict
```

### 4.6 评审结果缺少长期治理

当前评审可以驱动单次自动修订，但还不能：

- 查询某章历史评审。
- 聚合某卷质量趋势。
- 标记作者接受的风险。
- 忽略不适合当前作品的评审建议。
- 区分自动修订成功与未解决问题。

需要增加评审状态和作者决策记录，避免系统重复提出已经明确接受的问题。

## 5. 开发优先级

当前阶段状态：

| 阶段 | 状态 | 当前结论 |
| --- | --- | --- |
| P0-1 章节生产结果结构化持久化 | 未开始 | 下一项开发任务 |
| P0-2 章节确认 Workflow | 未开始 | 依赖 P0-1 |
| P0-3 章节记忆提取与人工确认 | 未开始 | 依赖 P0-2 |
| P0-4 下一章继承确认后的状态 | 未开始 | 依赖 P0-3 |
| P1 长期创作效率与资产治理 | 未开始 | P0 完成后进入 |
| P2 稳定连载和运维能力 | 未开始 | P1 核心能力稳定后进入 |

### 5.1 P0：章节确认与记忆闭环

P0 的目标是让一章正式成为下一章可靠的生产资料。

#### 阶段一：章节生产结果结构化持久化

实现内容：

- 独立保存章节初稿、最终候选稿和每轮修订稿。
- 保存章节评审报告。
- 保存修订历史。
- 保存质量门禁结果。
- 保存每次 AgentRun。
- Workflow 完成后章节状态进入 `waiting_for_user`，而不是业务意义上的正式完成。

验收标准：

- 同一个 `taskId` 可以追踪全部草稿、评审、修订和 AgentRun。
- 数据均能通过 `novelId`、`chapterNo`、`chapterPlanId` 关联。
- Workflow 失败不会生成正式章节。
- 重新读取任务后可以完整还原当时的生成结果。

#### 阶段二：章节确认 Workflow

实现内容：

- 新增章节确认和拒绝操作。
- 确认时选择候选版本。
- 创建正式章节版本。
- 更新章纲和小说进度。
- 保留确认来源和确认时间。
- 禁止跨小说确认章节。

验收标准：

- 只有待确认候选稿可以确认。
- 同一章节同时只有一个当前正式版本。
- 重复确认具备幂等或明确冲突行为。
- 拒绝不会污染正式章节和 canon。
- 下一章上下文只读取已确认章节作为权威正文。

#### 阶段三：章节记忆提取与人工确认

实现内容：

- 新增记忆 Agent 或等价的稳定 capability。
- 从确认章节提取章节摘要、canon 候选、角色状态变化、关系变化、时间线事件和伏笔变化。
- 提取结果先保存为待确认记忆变更集。
- 允许作者接受、修改或拒绝单项变更。
- 只有确认后的变更才能写入正式记忆。

验收标准：

- 草稿正文不能直接进入 canon。
- 每条记忆可以追溯到章节和版本。
- 角色状态变化保留前后值。
- 伏笔变化区分新增、推进、回收和风险。
- 相互冲突的 canon 事实不能静默写入。

#### 阶段四：下一章继承确认后的状态

实现内容：

- 章节上下文装配读取正式章节摘要和记忆。
- 优先读取结构化角色状态、世界规则、伏笔和 canon。
- 增加章节 readiness 检查。
- 缺少关键资产时给出明确错误或风险，不静默降级。

验收标准：

- 确认第 N 章后，第 N+1 章能读取其摘要、结尾和状态变化。
- 不同小说之间不存在记忆串用。
- 角色、设定或 canon 冲突能够在生成前暴露。
- 上下文来源可通过 CLI 查询。

### 5.2 P1：长期创作效率与资产治理

P1 在 P0 闭环稳定后实施。

#### 章节版本管理

- 查询章节版本历史。
- 比较任意两个版本。
- 从正式版本生成修改候选。
- 场景重写、扩写、压缩和润色均创建新版本。
- 支持将历史版本重新设为当前候选，但不删除审计记录。

#### 章纲维护

- 修改单章章纲。
- 批量生成后续章纲。
- 插章、删章、拆章和合章。
- 章号重排和引用迁移。
- 已确认章节保护。
- 卷目标、章纲目标和伏笔计划一致性检查。

#### 结构化资产命令

- 角色查询和状态历史。
- 世界规则查询和冲突检查。
- 时间线按故事时间和叙事顺序查询。
- 伏笔按状态、卷和计划回收章节查询。
- canon 查询、来源追踪和冲突处理。

#### 上下文解释

- 展示实际上下文包。
- 展示来源引用和记忆命中。
- 展示缺失、压缩和省略内容。
- 支持生成前 dry-run。
- 支持上下文窗口和 token 预算策略。

#### 评审与作者决策

- 查看历史评审和未解决问题。
- 按卷聚合质量趋势。
- 记录作者接受风险、忽略建议和作品级偏好。
- 评审和修订 Agent 读取作者决策。

P1 验收标准：

- 作者可以不打开 SQLite 或 JSON 文件完成常用资产查询。
- 所有修改都有版本和来源记录。
- 已确认章节和 canon 不会被大纲或章节修改静默破坏。
- 评审不会持续重复作者已经明确接受的问题。

### 5.3 P2：稳定连载和运维能力

#### 任务恢复

- 任务取消、重试和恢复。
- 保存 Workflow 步骤状态和恢复点。
- 从失败步骤继续，而不是默认重新执行全部模型调用。
- 区分可重试错误和不可重试输入错误。

#### 使用统计

- 按小说、章节、Workflow、Agent 和模型统计 token。
- 统计生成、评审和修订调用次数。
- 统计章节质量分和修订轮数趋势。
- 为后续成本估算保留价格配置接口，但暂不做前端配置。

#### 导入、导出与备份

- 导出单章、章节范围和整本小说 Markdown。
- 导出完整结构化 JSON。
- 备份 SQLite、正文和资源清单。
- 恢复前校验版本和小说标识。

#### CLI 使用体验

- 支持 `$EDITOR` 编辑长文本。
- 支持从文件读取创作指令。
- 支持流式输出和主动中断。
- 提供正文及大纲彩色 diff。
- 提供命令补全和更清晰的交互提示。

P2 验收标准：

- 长任务失败后能够保留已有成果。
- 作者能够知道模型调用成本和质量变化。
- 小说项目可以脱离当前数据库进行备份、迁移和恢复。
- 日常写作不需要频繁手写长参数或读取原始 JSON。

## 6. 推荐实施顺序

后续默认按以下顺序推进：

```txt
章节生产结果结构化持久化
-> 章节确认 Workflow
-> 记忆变更提取与人工确认
-> 正式记忆写入
-> 下一章上下文继承
-> 章节版本管理
-> 单章和批量章纲维护
-> 角色、时间线、伏笔和 canon 命令
-> 评审治理和作者决策
-> 任务恢复、统计、导出和 CLI 体验
```

除非出现阻塞性基础问题，不应在 P0 完成前优先投入以下内容：

- 批量自动生成大量章节。
- 新增更多顶层 Agent。
- 阅读数据分析。
- 复杂向量数据库。
- 可视化 Agent 编排器。
- Agent、Prompt、Skill 或 Workflow 配置 UI。
- 与小说平台账号或自动发布能力集成。

## 7. 模块落点建议

| 能力 | 主要落点 |
| --- | --- |
| 章节版本、评审、AgentRun 和质量门禁模型 | `packages/domain`、`packages/db` |
| SQLite 读写和事务 | `packages/db` |
| 面向 Workflow 的资产访问 | `packages/repositories` |
| 记忆提取、查询、冲突和正式写入 | `packages/memory` |
| 章节确认、记忆确认和恢复编排 | `packages/workflow` |
| 记忆 Agent 和章节相关 capability | `packages/agents` |
| 本地作者操作入口 | `packages/agent-cli` |
| 跨包稳定类型和纯工具 | `packages/shared`，仅在出现真实复用后引入 |

当前阶段默认不修改 `apps/web` 和 `apps/api`。上述能力必须先通过类型检查、构建、fake model CLI 冒烟和临时 SQLite 验证稳定，再单独规划接入。

## 8. 开发约束

后续实现必须继续遵守：

1. 所有小说私有资产必须绑定 `novelId`。
2. 未确认草稿不得进入正式 canon。
3. Agent 只输出草案、候选、补丁、提取结果或评审报告。
4. Workflow 负责状态、人工确认、质量门禁和写入边界。
5. Repository 负责资产读写，不在 Agent Prompt 内直接访问数据库。
6. 已确认章节、大纲和 canon 的修改必须保留版本和来源。
7. 失败任务必须保存错误信息，不得留下半完成的正式资产。
8. 外部学习源只用于方法论提炼，不复制未授权长文本或受限制源码。
9. 新增 Agent 或 Workflow 能力时优先提供 fake model CLI 入口和 SQLite 临时库手工验证路径。
10. 当前正文方向继续由 `chapter` Agent 承接，不新增顶层“生成 Agent”或“修改 Agent”。

## 9. 路线图维护规则

每完成一个阶段，应更新：

- 对应功能的当前状态。
- 实际落地文件和命令。
- 验收标准是否通过。
- 新发现的依赖、风险和延期事项。

状态统一使用：

- `未开始`
- `进行中`
- `可验证`
- `已完成`
- `暂缓`

只有同时满足以下条件，功能才能标记为“已完成”：

1. 核心代码已落地。
2. 有可重复的类型检查、构建或手工冒烟命令。
3. SQLite 或对应本地资产经过真实读写验证。
4. CLI 可以触达该能力，或明确说明它是仅供内部调用的底层能力。
5. 相关中文文档已经同步。

## 10. 当前里程碑

当前里程碑定义为：

> 完成确认后的章节资产与小说记忆闭环，使已确认章节能够可靠地成为下一章生产的权威上下文。

该里程碑完成前，项目的章节生产能力仍应视为可验证的草稿生产系统，而不是完整的长篇连载生产系统。
